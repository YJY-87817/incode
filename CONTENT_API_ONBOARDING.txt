[incode2 Content API 新人導覽 - 第一版]

這份文件給「剛接手 content API 的新人」，先建立全局地圖，再看資訊流、卡控點、前後端配合方式。
你可以先看完大綱，再挑任一段深入問我。

==================================================
0) 先看大綱（先建立腦中地圖）
==================================================

A. 專案骨架（從根目錄角度）
- `incode2/Program.cs`：整體啟動設定（DI、CORS、Cookie Auth、路由）
- `incode2/ApiControllers/Content/*`：Content 對外 API 入口
- `incode2/Services/Contents/*`：內容領域商業邏輯（真正核心）
- `incode2/Services/Point/*`：點數、打賞、委託任務獎勵相關流程
- `incode2/Models/*` + `incodedatabaseContext.cs`：資料表與關聯
- `incode2/Dtos/Content/*`：API Request/Response 契約
- `incode2/Controllers/Contents/*` + `Views/Content*`：後台 MVC/Razor 管理頁（不是前台論壇 API）

B. 一次 API 呼叫的主路徑
前端(通常 Vue) -> `ContentApiController` -> `ContentService` -> `DbContext` -> SQL
                                   -> `ContentInteractionService`（讚/收藏/隱藏）
                                   -> `PointLogService`（打賞）
                                   -> `EntrustMissionService`（委託任務）

C. 主要卡控（你要先記住）
- 身分：`User.GetId()` 取 Claim `NameIdentifier`
- 權限：更新/刪除只允許作者本人
- 參數：`ModelState`、數值 > 0、防無效查詢
- 狀態：`IsActive == 1` 視為有效內容；刪除是軟刪除（改狀態）
- 交易：委託任務最佳解答、打賞會做 transaction

D. 前後端協作關鍵
- Cookie 跨域 + CORS（`AllowCredentials`）
- 前端呼叫 API 要帶 credentials，後端才能拿到登入身份
- 回應 payload 內含分頁欄位 (`totalCount`, `page`, `totalPages`) 與互動欄位 (`MyInteractions`)


==================================================
1) 從根目錄看結構（你在 content 工作時最常碰）
==================================================

1-1. 啟動與組態
- 檔案：`incode2/Program.cs`
- 你要注意的三件事：
  1) DI 註冊
     - `IContentService -> ContentService`
     - `IContentInteractionService -> ContentInteractionService`
     - `IContentEntrustMissionService -> ContentEntrustMissionService`
     - `IPointLogService -> PointLogService`
     - `IEntrustMissionService -> EntrustMissionService`
  2) CORS (`VueApp` policy)
     - 允許多個 localhost / ngrok origin
     - `AllowCredentials()` 代表可以帶 Cookie
  3) Auth Scheme
     - 前台會員 Cookie: `Incode.Member`（`MemberAuth`）
     - 後台管理 Cookie: `Incode.Admin`（`AdminAuth`）
     - API 未授權時，不 redirect，直接回 401/403（很重要，前端比較好處理）

1-2. Content API 入口
- 檔案：`incode2/ApiControllers/Content/ContentApiController.cs`
- 這支是 content 主幹，幾乎所有論壇內容讀寫都在這邊進入 service。

1-3. Content 商業邏輯核心
- 檔案：`incode2/Services/Contents/ContentService.cs`
- 你可以把它當成「規則中心」：
  - 查詢與分頁
  - 型別過濾
  - 回覆統計
  - Like 數彙整
  - 內容建立/編輯/刪除
  - 內文存檔策略（html 存檔 + DB 只存路徑）

1-4. Interaction（讚/收藏/隱藏/檢舉/最佳解答）
- Controller：`ContentInteractionApiController.cs`
- Service：`ContentInteractionService.cs`
- 關鍵：有些互動值是用 `InteractionCategoryId` 硬編碼映射（例如 1=Like）

1-5. 委託任務和點數
- 發佈貼文+委託：`ContentEntrustMissionService.cs`
- 任務主流程：`EntrustMissionService.cs`
- 點數交易：`PointLogService.cs`

1-6. 資料模型
- `Models/Content.cs`
- `Models/ContentInteraction.cs`
- `Models/ContentCategory.cs`
- `Models/EntrustMission.cs`
- 全關聯設定在 `Models/incodedatabaseContext.cs`

2) Content API 逐段資訊流（從 request 到 DB）
==================================================

2-1. 列表查詢 `GET /api/ContentApi`
- Controller：接 query 參數（categoryId, keyword, types, sortBy, page, pageSize）
- Controller：取 `userId = User.GetId()`，未登入時用 null
- Service：
  1) `ParseTypes()` 處理 `types=1,2,3`
  2) 篩 `IsActive == 1`
  3) 如果登入，排除被自己「隱藏」的內容（interaction category 2）
  4) 套用 category/keyword/type/sort
  5) 分頁 + 投影欄位
  6) 額外查回覆統計、like 統計、是否有進行中的委託任務
  7) 組成 `ContentListResponseDto`
- 回傳：`items + totalCount + totalPages + currentPage + pageSize`

卡控重點：
- 無效 types（傳了但 parse 不出數字）會直接回空結果，不爆錯。
- keyword 不會去讀 `body` 檔案內容（若 body 是 `/contents/xxx.html` 路徑時不做文字搜尋）。


2-2. 取單篇 `GET /api/ContentApi/{id}`
- Service 查 `IsActive == 1` 的內容
- 補算：回覆數、最後回覆時間/人、like 數、當前使用者互動狀態
- 回傳 `ContentDto`

卡控重點：
- 找不到就 404
- `MyInteractions` 會依登入使用者不同而改變


2-3. 建立貼文 `POST /api/ContentApi`
- Controller：`dto.UserId = User.GetId()`（直接覆蓋，防止前端偽造）
- Service：
  1) 若有 `ParentContentId`，繼承父文 `CategoryId`
  2) 將 `Body` html 寫入 `wwwroot/contents/content-*.html`
  3) DB 的 `Body` 欄位只存路徑 `/contents/xxx.html`
  4) 寫入 `Content`

卡控重點：
- 目前這支 API 沒有 `[Authorize]`，如果沒登入 `UserId` 會是 0（需確認你們業務是否允許）
- 內文儲存策略是「檔案路徑化」，不是直接存純文字內容


2-4. 建立貼文 + 委託任務 `POST /api/ContentApi/with-entrust-mission`
- 必須登入（Controller 自行檢查 userId > 0）
- Service 流程：
  1) 建立內容（同上）
  2) 建立 EntrustMission
  3) EntrustMission 建立時觸發預扣點數（reserve）
- 失敗回傳：`ResultDTO` 會含錯誤 code/message，且帶部分資料

卡控重點：
- 任務賞金不足、內容不存在、截止時間非法，都在 EntrustMissionService 擋下
- 有 transaction，避免任務/點數狀態不一致


2-5. 更新內容 `PUT /api/ContentApi/{id}`
- Service：
  1) 先找內容
  2) 比對 `content.UserId == currentUserId`
  3) 寫 `ContentHistory` 備份舊 title/body
  4) 新 body 再存成新 html 檔路徑
  5) 更新 title/body/updatedAt

卡控重點：
- 非作者更新會失敗（目前與 NotFound 共用回傳，前端要注意）


2-6. 刪除內容 `DELETE /api/ContentApi/{id}`
- 必須登入
- Service 驗證作者本人
- 不做實體刪除，改 `IsActive = 2`（軟刪除）

卡控重點：
- 軟刪除對查詢結果有直接影響（列表只撈 `IsActive == 1`）


2-7. 取回覆/子回覆
- `GET /api/ContentApi/{id}/comments`
- `GET /api/ContentApi/{id}/children?types=2,3&page=1&pageSize=20`
- 都會走 `GetChildrenByContentId`，只是 comments 用全量模式。


2-8. 取「我的內容」系列
- `GET /api/ContentApi/me/posts` (type=1)
- `GET /api/ContentApi/me/replies` (type=2)
- `GET /api/ContentApi/me/comments` (type=3,4)
- `GET /api/ContentApi/me/liked-contents`
- `GET /api/ContentApi/me/bookmarked-contents`

卡控重點：
- 全都要求已登入（`userId > 0`）
- 這幾支回傳時額外包了舊欄位（`count`）做向下相容


2-9. 打賞 `POST /api/ContentApi/{id}/tip`
- `[Authorize]`
- Controller 檢查 amount > 0、內容存在
- Service (`PointLogService.TipAsync`)：
  1) 不可打賞自己
  2) 檢查餘額
  3) 交易中同時扣款/加款
  4) 寫兩筆 PointLog


==================================================
3) Interaction 流程（讚、收藏、隱藏、最佳解答）
==================================================

3-1. API 入口
- `incode2/ApiControllers/Content/ContentInteractionApiController.cs`

3-2. Toggle 行為
- `POST /api/ContentInteractionApi`
- 同一 user + content + category：存在就移除，不存在就新增
- 回傳 `isRemoved` 告知前端現在是新增還取消

3-3. 常見分類映射（程式內目前使用）
- `1` = Like
- `2` = Hide
- `3` = Bookmark
- `4` = Report
- 最佳解答分類會用名稱去 `interaction_category` 找 (`best_answer`, `accepted`, `最佳解答`...)

3-4. 最佳解答流程（跨 content + point + mission）
- `POST /api/ContentInteractionApi/best-answer`
- 核心卡控：
  - 只有任務發起者可選
  - 不能選自己回覆
  - 選到的內容必須屬於該任務主文樹
  - 已有最佳解答不可重複選
- 成功後：
  1) 消耗預扣點數
  2) 發放點數給解答者
  3) 任務狀態改 completed
  4) 寫一筆 content_interaction 當最佳解答記號


==================================================
4) 前後端如何配合（你要跟前端對齊的點）
==================================================

4-1. 身分與 Cookie
- 後端用 Cookie + Claim，不是 JWT。
- 前端要帶 credentials（例如 axios/fetch 設定）才能讓後端取得 `User.GetId()`。

4-2. CORS
- `Program.cs` 的 `VueApp` policy 已允許多個前端 origin。
- 若前端換 domain/port，這裡要同步更新。

4-3. API 錯誤語意
- 驗證錯誤：400
- 未登入：401
- 無權限：403
- 找不到：404
- 狀態衝突：409
- 伺服器錯：500

4-4. 分頁契約
- 列表 API 通常會回：`items`, `totalCount`, `page/pageSize` 或 `currentPage`
- 前端要注意不同 API 欄位命名有些歷史差異（例如 `count` 與 `totalCount`）

4-5. 內容 body 的特殊點
- DB 裡 `Body` 很可能是 `/contents/xxx.html`，不是完整 html 內容
- 前端如果要顯示全文，需再載該靜態檔或透過既有渲染策略處理

6) 新人常見疑問（先幫你踩點）
==================================================

Q1: 為什麼 body 要存成檔案路徑？
A: 目前設計是把 html 寫到 `wwwroot/contents`，DB 只留 URI。好處是 DB 輕；代價是要處理檔案生命週期。

Q2: 為什麼某些 API 未加 `[Authorize]` 仍可取得 userId？
A: `User.GetId()` 未登入會回 0。是否允許匿名操作取決於 controller/service 的額外判斷。

Q3: 如何判斷某文章有沒有被我按讚/收藏？
A: 看 `MyInteractions`（含布林欄位與 map/categorie）。

Q4: 刪除後資料去哪？
A: 軟刪除，`IsActive` 改為 2，不是硬刪。

Q5: 最佳解答和一般 like 的差別？
A: 最佳解答有任務狀態和點數結算副作用，且只允許特定角色操作。

8) 目前觀察到的實務提醒（先當風險清單）
==================================================

- `Program.cs` 有重複 `MapControllers()` / `UseRouting()` / `UseCors()` 設定，長期建議整理。
- `UpdateContent` 非作者時回傳與「找不到」同語意，前端若要精準提示可再區分。
- `CreateContent` 沒有 `[Authorize]`，是否允許匿名發文需要產品確認。
- Interaction Category ID 有硬編碼（1/2/3/4），若資料表改值會影響邏輯，建議後續抽常數。
